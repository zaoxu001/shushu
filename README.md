# shushu · 术数核心算法

中国术数的计算内核。只做计算，不做解释。

输入是时间和地点，输出是结构化的判断：四柱、藏干、十神、五行力量、日主旺衰、
调候用神、月令格局、用喜忌仇闲、岁运引动、逐年起伏。

**这个包里一句「你今年会如何如何」都没有。** 它只告诉你「流年地支冲月令」「用神为火」
「日主偏弱 ratio 0.41」这样的事实与判断，怎么说成人话是调用方的事。

这条边界是刻意的。措辞是产品的脸面，改动频率远高于算法；算法能写测试断言，措辞不能。
两者混在一起，算法就会被迫跟着文案发版。

## 为什么再造一个

市面上的开源项目多半停在排盘。`lunar-python` 把历法和四柱做得很好，本包直接依赖它，
不重复造天文计算。但排盘之上那一层——旺衰怎么量化、用神怎么取、格局怎么定——
要么没有，要么各写各的、彼此矛盾。

本包想把这一层做成可以被检验的样子：

- **有出处的规则，注明出处。** 调候查《穷通宝鉴》十天干乘十二月令一百二十格；
  格局按《子平真诠》月令取格与顺用逆用；旺衰参考《滴天髓》「月令不可独断」。
- **工程近似的系数，老实承认。** 打分权重这类无法从典籍直接推出的数字，
  一律做成模块级常量，标注「本包取值，可调」，不假装它有出处。
- **流派分歧的地方，不替使用者选边。** 晚子时归哪一天、阴干有没有刃、取用优先级
  是格局优先还是调候优先，都做成参数，默认值写明理由。

## 用

```python
from datetime import datetime
from shushu.bazi import chart, strength, yongshen

c = chart.build_chart(datetime(1996, 4, 18, 14, 6), longitude=114.93, gender=0)
print(c.year.ganzhi, c.month.ganzhi, c.day.ganzhi, c.hour.ganzhi)
# 丙子 壬辰 乙酉 癸未

s = strength.day_master_strength(c.quad)
print(s.label, round(s.ratio, 3))
# 中和 0.5xx

y = yongshen.select(c.quad)
print(y.yong, y.xi, y.ji, y.chou)
# 用神 喜神 忌神 仇神
```

## 分层

| 层 | 模块 | 做什么 |
|---|---|---|
| 历法 | `shushu.calendar` | 真太阳时、节气时刻、距节天数 |
| 通用 | `shushu.core` | 五行生克、干支属性藏干、合冲刑害、长生、旺相休囚死 |
| 排盘 | `shushu.bazi.chart` | 四柱、藏干、司令、纳音、地势、命宫身宫胎元 |
| 排运 | `shushu.bazi.luck_cycle` | 起运、大运、流年、流月 |
| 量化 | `shushu.bazi.strength` | 五行力量、日主旺衰、十神力量、寒暖燥湿 |
| 取用 | `shushu.bazi.tiaohou` `geju` `yongshen` | 调候、格局、用喜忌仇闲 |
| 引动 | `shushu.bazi.interact` `score` | 岁运对原局的作用、逐年起伏 |
| 双盘 | `shushu.bazi.hepan` | 两张盘的关系指标 |
| 参考 | `shushu.bazi.shensha` | 神煞。取用逻辑不采信，仅为完整性提供 |

`core` 和 `calendar` 是跨术共用的，将来加六壬、奇门都从这里长。

## 不做什么

不做文案，不做吉凶断语，不做建议。不读系统时间，不碰网络和文件（除了包内自带的数据表）。
不替使用者在流派分歧上选边。

## 数据来源

调候用神表整理自《穷通宝鉴》（又名《栏江网》），喜忌表整理自《金不换大运》，
人元司令分日表为通行本，六十四卦、二十八宿等为公共领域的典籍常识。
这些古籍均已过版权保护期。
